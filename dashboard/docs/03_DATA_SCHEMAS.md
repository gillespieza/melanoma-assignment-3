## B. Q1 ML predictions (generated by the user locally)

Produced by `q1-response-predictor/q1_infer.py` → `q1_predictions.csv`, auto-copied to
`dashboard/public/q1_predictions.csv`. **This is the blocking dependency.**

### `q1_predictions.csv` schema

```
SAMPLE_ID, PATIENT_ID, cohort,
IFN_gamma, TIS, CYT, CD8_Tcell, IMPRES, PD_L1,     # the 6 model input features
prob_lr, prob_rf, prob_xgb, prob_svm, prob_enet,   # per-model P(response)
prob_ensemble,                                     # mean of the above → USE THIS as pResponse
pred_label,                                         # 0/1 at 0.5 threshold
actual_response,                                    # 0/1 where known (Liu/Hugo/Riaz); NaN for TCGA
os_months
```

- `cohort` ∈ {`Liu 2019`, `Hugo 2016`, `Riaz 2017`, `TCGA-SKCM`}.
- The **TCGA-SKCM** rows are the ones that join to the Q3 cohort (match on `PATIENT_ID`).
- The trial cohorts have real `actual_response` labels → use them to show the model's
  real accuracy (a compelling "our AI is right X% of the time" panel).

### Join key

Q3 CSVs use `PATIENT_ID` like `TCGA-3N-A9WB`. `q1_predictions.csv` TCGA rows should have
the same. Join on `PATIENT_ID` (fall back to `SAMPLE_ID` prefix if needed).

## C. `cohort.json` — the file the app consumes (GENERATE THIS)

One array of patient objects. Suggested schema:

```jsonc
{
  "meta": { "generated": "ISO date", "nQ3": 421, "nQ1Tcga": 0, "doseAxis": [0.01, ...] },
  "patients": [
    {
      "id": "TCGA-3N-A9WB",
      "sampleId": "TCGA-3N-A9WB-06",
      "braf": "V600E" | "WT",          // from BRAF_MUT (1→V600E label, 0→WT)
      "nras": "Mutant" | "WT",
      "pdl1Expr": 0.167,                // raw CD274
      "pdl1Pct": 41,                    // percentile-ranked 0–100
      "brafiCurve": [10 numbers],       // real tumour_burden BRAFi sweep
      "antipd1Curve": [10 numbers],     // real checkpoint antiPD1 sweep
      "brafiReduction": 0.48,           // 1 - min(brafiCurve)/brafiCurve[0]
      "antipd1Reduction": 0.02,         // 1 - min(antipd1Curve)/antipd1Curve[0]
      "q1": {                           // null until q1_predictions.csv exists
        "pResponse": 0.62,
        "perModel": { "lr":0.6, "rf":0.7, "xgb":0.55, "svm":0.6, "enet":0.65 },
        "features": { "IFN_gamma":.., "TIS":.., "CYT":.., "CD8_Tcell":.., "IMPRES":.., "PD_L1":.. },
        "cohort": "TCGA-SKCM"
      },
      "q4": { "resistanceRisk": "low|moderate|high", "flags": ["SOX10-dependent", ...] }
    }
  ]
}
```

### Generation approach

Write `dashboard/scripts/build_cohort.mjs` (Node) or a small Python script that:
1. Reads `/tmp/tumour.csv` + `/tmp/checkpoint.csv` (from the git extraction above).
2. Joins on `SAMPLE_ID`; computes `pdl1Pct` (percentile of CD274), `brafiReduction`,
   `antipd1Reduction`.
3. If `public/q1_predictions.csv` exists, joins TCGA rows on `PATIENT_ID` → fills `q1`.
   Else leaves `q1: null`.
4. Derives simple `q4` flags (e.g. resistanceRisk from residual burden at max dose;
   flags placeholder from BRAF/NRAS/MAPK_DRIVEN — keep honest, label as heuristic).
5. Writes `public/cohort.json`.

Keep the generator idempotent so it can be re-run after the user drops in the real
`q1_predictions.csv` (Q1 lane then lights up with zero code changes).

## D. Q2 / Q4 evidence (cohort-level, not per-patient)

- **Q2** cell-line validation: present as an evidence chip row / short factual panel. Pull
  wording from `q1-response-predictor/reports/` if specifics are needed; otherwise a concise
  "signature tracks drug sensitivity in melanoma cell lines" statement.
- **Q4** resistance: SOX10 dependence + known BRAFi-resistance escape (MAPK reactivation,
  PD-L1 upregulation). Per-patient flags are heuristic — label them as such.
